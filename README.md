## 강림이 (kangrimi)

강남대학교 26개 게시판의 공지를 한 앱에 모으고, 구독한 키워드의 공지가 올라오면 푸시로 알려주는 서비스입니다.
2인 팀으로 기획부터 함께 했고, 백엔드 전체와 배포·운영을 맡았습니다. App Store와 Google Play에 출시했고 누적 다운로드는 약 800회입니다.

### 개선 결과

| 항목 | 전 | 후 |
| :--- | ---: | ---: |
| 공지 상세 API 처리 시간 (평균) | 832ms | 5 ~ 11ms |
| 1초를 넘는 상세 응답 | 4 / 20건 | 0 / 600회 |
| 가장 무거운 게시판의 목록 1페이지 | 2.2MB | 6.7KB |
| 26개 게시판 1페이지 응답 합계 | 3.5MB | 188KB |
| 푸시 발송 대상 게시판 | 5 / 26개 | 26 / 26개 |
| 달구지 시간표 동기화 | 연 365회 | 연 33회 |
| 백엔드 자동 테스트 | 50개 | 141개 |

상세 응답 시간은 네트워크를 제외한 서버 내부 처리 시간이고, 로컬 환경에서 측정했습니다.
목록은 응답 크기 기준이며, 같은 DB 스냅샷에 수정 전후 코드를 각각 실행해 비교했습니다.

### 문제를 푼 과정

| 문제 | 원인 | 조치 |
| :--- | :--- | :--- |
| 목록 응답이 최대 2.2MB | 본문이 아니라(평균 약 340자) 과거 공지 일부에 저장된 base64 이미지(행당 최대 약 130만 자) | 목록은 앱이 쓰는 필드만 응답하고 본문·이미지·첨부는 지연 로딩. 앱 코드 변경 없음 |
| 구독해도 알림이 오지 않음 | 앱은 26개 게시판 구독을 받는데 서버는 5개만 발송. 2026년 6월 스냅샷 기준 구독 183건 중 66건(36%)이 해당 | DB 발송 이력으로 원인을 찾아 발송 대상을 26개 전체로 확대 |
| 외부 AI 리뷰의 Critical 6건 | 실제 코드, DB, API 응답과 대조하니 Critical로 남은 것은 1건. 나머지는 재현 불가 또는 원인이 다름 | 검증 후 필요한 수정만 적용해 잘못된 진단 기반의 수정을 피함 |
| 안드로이드에서 공지 이미지가 열리지 않음 | 학교 서버가 중간 인증서를 보내지 않음 | 서버 측 이미지 프록시. 도메인 화이트리스트와 리다이렉트 단계별 검사로 SSRF 차단, 프록시 URL에 HMAC 서명 |
| 신규 공지 배치 전체가 롤백됨 | 정기·초기·수동 크롤링이 겹쳐 유니크 제약 위반 | 크롤링 진입점을 하나로 모으고 공용 락으로 직렬화. 실패한 알림은 24시간 안에서 재전송 |
| 공지 상세 응답에 약 1초 소요 | 캐시가 없으면 학교 사이트를 먼저 크롤링 | DB 내용을 즉시 응답하고 갱신은 백그라운드에서 URL당 10분에 한 번 |
